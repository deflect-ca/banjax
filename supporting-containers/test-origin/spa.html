How to test

  1. Open this page at http://localhost/spa. Use localhost or https: otherwise the browser sends no Sec-Fetch-* headers, and only the XHR button (which sends X-Requested-With) is recognised as an XHR.
  2. Leave polling on. Calls should show OK.
  3. Send a kafka challenge for this site from the repo root: 
    docker compose run --rm kafka-cmd-tester -cmd challenge_all -host localhost
    or for this browser's session only: 
    (loading session id...)
  4. API calls now show CHALLENGE REQUIRED: a 403 with {"error": "challenge_required"}. They don't count toward the failed challenge ban, so polling can carry on.
  5. Click Reload to verify (or tick auto-reload) to get the challenge as a page, solve it, and come back: calls are OK again.

Compare with curl -H 'Accept: application/json' http://localhost/spa/api/feed while challenged: not an XHR, so it gets the HTML challenge (429) and does count toward the ban.
